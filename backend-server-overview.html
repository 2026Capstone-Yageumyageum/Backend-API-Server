CAPSTONE BACKEND API SERVER

백엔드 서버 한눈에 보기

이 서버는 사용자 인증, 영상 메타데이터, 프로 스켈레톤 기준 데이터, Python 투구 분석 서비스 호출, 그리고 Top 3 유사도 결과 저장을 담당하는 Spring Boot API 서버입니다.

Kotlin 2.2.21 Spring Boot 4.0.6 Java 21 JPA + PostgreSQL Redis Refresh Token Python API: 127.0.0.1:5020
앱 진입점 BackendServerApplication.kt
주요 사용자 API POST /api/analysis/{videoId}
Python 캐시용 내부 API GET /api/internal/analysis/reference-models
보안 방식 JWT Bearer, stateless session

전체 아키텍처

사용자 앱은 JWT로 백엔드에 요청하고, 백엔드는 Python 분석 서버로 영상을 넘깁니다. Python은 백엔드 내부 API에서 프로 스켈레톤 기준 데이터를 cache로 읽은 뒤 유사도를 계산합니다.

투구 분석 요청 흐름

1

클라이언트가 분석 요청

JWT가 있는 사용자가 POST /api/analysis/{videoId}로 영상 파일을 업로드합니다.

Controller: AnalysisController.kt

2

UserVideo 조회

백엔드는 path variable의 videoId로 기존 영상 레코드를 찾습니다. 없으면 404 성격의 예외가 납니다.

Repository: UserVideoRepository

3

Python으로 multipart 전송

백엔드는 파일을 userVideo part로, 분석 정보는 metadata part로 보내며 endpoint는 /api/analyze입니다.

Client: WebClientConfig.kt

4

Python 응답 수신

Python은 사용자 skeleton CSV와 players Top 3를 반환합니다. 응답은 AnalysisResponse DTO로 매핑됩니다.

DTO: AnalysisDto.kt

5

DB 저장

사용자 skeleton은 skeleton_data에 TEXT로 저장되고, analysis_result에는 Top 3 점수와 reference 연결이 저장됩니다.

Service: AnalysisService.kt

중요: JPA 저장은 blocking 작업이므로 현재 서비스는 reactive pipeline 중간에 Schedulers.boundedElastic()로 스레드 풀을 전환합니다.

인증 흐름

로그인 / 회원가입

  1. 클라이언트가 Google ID token을 POST /api/auth/google로 전송합니다.
  2. 백엔드가 Google token audience를 검증하고 email을 추출합니다.
  3. 기존 사용자면 access token과 refresh token을 발급합니다.
  4. 새 사용자면 회원가입 필요 응답을 반환하고, POST /api/auth/signup에서 nickname을 받습니다.

토큰 갱신

  1. refresh token은 Redis의 refreshToken keyspace에 TTL과 함께 저장됩니다.
  2. POST /api/auth/refresh 요청이 오면 기존 refresh token을 검증합니다.
  3. 사용한 refresh token은 삭제하고 새 access/refresh token을 다시 발급합니다.

데이터 모델

핵심 관계는 사용자 1명에 여러 영상이 있고, 각 영상은 분석 후 사용자 skeleton을 1개 가질 수 있으며, 분석 결과는 사용자 영상과 프로 reference model을 연결합니다.

users

  • id: 사용자 PK
  • email: Google email, unique
  • nickname: 서비스 닉네임
  • status: 기본 ACTIVE

user_video

  • user_id: users FK
  • video_url: 업로드 영상 위치
  • status: 기본 PENDING
  • skeleton_data_id: 분석 후 사용자 skeleton 연결

skeleton_data

  • skeleton_data: Python CSV text
  • frame_count: 프레임 수
  • fps: Double
  • resolution: 예시 1080x1920

reference_model

  • pitcher_name: 프로 선수명
  • pitch_type: 구종
  • source_url: 원본 출처 또는 파일 위치
  • skeleton_data_id: 프로 skeleton 연결

analysis_result

  • user_video_id: 사용자 영상 FK
  • reference_id: 프로 reference FK
  • similarity_score: Python Top 3 점수
  • feedback_text: 현재는 간단 요약 문자열

refreshToken

  • Redis 저장 모델입니다.
  • refreshToken: Redis key
  • userId: 사용자 ID
  • ttl: refresh 만료 시간

API 표면

메서드 경로 인증 역할 주요 파일
POST /api/auth/google Public Google ID token 검증 및 로그인 분기 AuthController.kt
POST /api/auth/signup Public email, nickname으로 사용자 생성 및 토큰 발급 AuthService.kt
POST /api/auth/refresh Public refresh token rotation RefreshToken.kt
POST /api/analysis/{videoId} JWT 필요 사용자 영상을 Python으로 보내고 Top 3 결과 저장 AnalysisService.kt
GET /api/internal/analysis/reference-models Public Python pro skeleton cache용 내부 feed InternalAnalysisController.kt
GET /swagger-ui/**, /v3/api-docs/** Public OpenAPI 문서 확인 SwaggerConfig.kt

로컬 실행 메모

일반 실행

기본 설정은 PostgreSQL을 기대합니다. Docker 없이 로컬에서 빠르게 확인할 때는 H2 override를 쓸 수 있습니다.

./gradlew bootRun

검증 명령

Kotlin 컴파일과 ktlint는 이 서버의 기본 품질 확인선입니다.

./gradlew compileKotlin
./gradlew ktlintCheck
주의: H2 메모리 DB로 실행하면 서버 종료 시 데이터가 사라집니다. 실제 팀 실행 환경에서는 PostgreSQL seed 또는 Docker DB 구성이 필요합니다.

현재 알고 있어야 할 설계 결정

항목 현재 결정 이유
Python 주소 http://127.0.0.1:5020 현재 로컬 분석 서버와 직접 연동하기 위함
Python endpoint POST /api/analyze Analysis_algorithm 서비스 계약과 통일
skeleton 저장 타입 TEXT Python이 현재 CSV text를 반환하므로 JSONB보다 단순하고 안전함
proId 타입 Python 문자열, Backend에서 Long 변환 reference_model.id 조회와 DB seed 숫자 ID를 맞추기 위함
응답 buffer Python WebClient 50MB skeleton CSV가 포함된 큰 JSON 응답을 받기 위함
분석 결과 조회 아직 별도 조회 API 없음 현재 구현은 요청과 저장 중심이며, 결과 표시 API는 후속 작업 필요
